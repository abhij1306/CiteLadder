# Programmatic SEO pilot

## Goal

Decide whether a repeatable family of pages is justified and, if so, specify a small pilot. Each page must give a distinct buyer something one good page could not.

## Where the data is

- `get_project_business_context`: the real products, locations, integrations or datasets behind each page.
- `read_search_dataset` and `read_performance`: demand for the pattern.
- `read_site_pages`: the pages that already exist.

## What good looks like

- Every combination is real: one office does not make nationwide local pages; an unbuilt integration is not an integration.
- Value comes from row data that changes the page, not swapped names. Say when one category page or tool would serve better.
- Do not add up volumes of overlapping variants; low volume can still serve a real need.
- A data contract: each field's source, owner, update frequency and what happens when it is missing. Rows without enough verified data stay unpublished.

## Deliver

One document: the pattern and why separate pages help, the data contract, a page template with conditional sections, a pilot table of three to five rows (URL, buyer task, data source, unique value, eligible or blocker), and the measures and stop rules before scaling.
